Что за продукт и все решения по нему — `PRODUCT.md`. Здесь — порядок работ.

## 1. Дизайн — сейчас

Решение Даши 09.10.2026: продукт — общий сайт для нескольких экзаменов (GRE и
TOEFL на старте, `PRODUCT.md`, «Экзамены»), и под это — редизайн. Структура
экранов остаётся, вид — новое направление вместо «Шагов»: сначала раунд 4 на
холсте — шесть экранов веба (главная «Тренировка» с выбором, вопрос, разбор,
статистика и история, выбор экзамена, карточка слова) в 3–4 направлениях,
светлая и тёмная тема, телефон и компьютер; после выбора — все экраны и
`DESIGN.md`, затем код: веб, потом Apple, потом Android.

Прежнее направление — «Шаги» (решение Даши 05.10.2026): свои цвета плюс родные
элементы каждой платформы (`PRODUCT.md`, «Platform»). Три раунда направлений —
на холсте Design (https://claude.ai/artifact/4pDFxjop5ddto1R6yjYm5H, копия —
`design/directions/`). Экраны телефона и компьютера нарисованы; токены —
`design/tokens` (как устроены — `docs/HANDOFF.md`), правила применения — `DESIGN.md`.

Имя бренда (без GRE, `PRODUCT.md`, «Brand Commitments») — перед бетой (решение
Даши 08.10.2026), до того — рабочее имя; свободно ли оно (домен, имя бота,
товарный знак) — проверить.

Конструктор тренировки обязан быть удобным при большом выборе — изучить, как
это делают лучшие приложения.

## 2. Каркас — первая задача кода

Допрос Даши 06.10.2026: каркас глубокий — на каждой платформе сквозной путь
«вход → экран «Сегодня» с данными с сервера → тесты → гейт». Продуктовые
решения допроса — в `PRODUCT.md` (привязка способов входа, офлайн, стенд,
адрес, мониторинг, копии базы, минимальные версии). Техника — по лучшим
практикам, версии сверены по первоисточникам 06.10.2026:

- **договор** — один файл `api/openapi.yaml` (OpenAPI 3.1, осторожное
  подмножество: без `oneOf`/`anyOf`, у каждого объекта
  `additionalProperties: false`); из него генерируются сервер Go (ogen —
  сам отклоняет лишние поля), веб и админка (Orval с проверкой каждого
  ответа по Zod), Swift (генератор Apple), Kotlin (openapi-generator).
  Сгенерированное коммитится, гейт проверяет, что оно свежее;
- **сервер** — Go 1.27, Postgres 18, запросы sqlc + pgx, миграции goose
  (SQL-файлы, встроены в бинарник, применяются до переключения на новую
  сборку), журнал `slog` (строка на запрос, id запроса в ответе), ошибки
  клиентов — таблица `client_errors`. Вход: initData — своя проверка подписи;
  Telegram, Apple, Google — go-oidc по ключам компаний. Сессия — случайный
  токен 256 бит, в базе только хэш; сайт — кука `__Host-` (HttpOnly,
  SameSite=Strict), мини-апп и приложения — заголовок `Authorization`. Тесты
  — настоящий Postgres, у каждого теста своя база-клон шаблона,
  `go test -race`, golangci-lint v2;
- **веб** — одно приложение для мини-аппа и сайта, оболочка выбирается при
  запуске; React 19 с React Compiler, Vite 8, TypeScript 7, TanStack Router и
  Query, CSS Modules на токенах, @tma.js/sdk-react; oxlint с проверкой типов,
  Vitest 5, Playwright (WebKit и Chromium, обе темы, axe), эталонные снимки —
  только в Docker-образе Playwright; Node 24 LTS, pnpm 12, рабочее
  пространство: `apps/web`, `apps/admin`, `packages/api-client`,
  `design/tokens`;
- **админка** — отдельное приложение (её код не попадает к людям), Base UI на
  наших токенах, вход Даши — Telegram и роль на сервере;
- **Apple** — SwiftUI, Swift 6, `@Observable`; iOS 18 / macOS 15, стекло на
  26+ с матовой подложкой ниже; токен — Keychain; Apple — родная кнопка,
  Google и Telegram — системное окно браузера (OIDC с PKCE); Swift Testing,
  XCUITest, снимки экранов; CI — раннер GitHub с Xcode 27;
- **Android** — Kotlin 2.4, Compose, Navigation 3, Hilt, minSdk 26, targetSdk
  37; токен — файл, зашифрованный ключом Keystore; Google — Credential Manager,
  Apple и Telegram — Custom Tab (#12); JUnit и Compose UI на Robolectric,
  Roborazzi; эмулятор — вне гейта (#14);
- **выкладка** — бинарник Go + systemd + Caddy + Postgres 18 из PGDG; откат —
  переключение на прошлую сборку; стенд — вторая копия рядом; копии базы —
  pgBackRest; локально — Postgres 18 в Docker на порту 55432 (порты соседних
  стеков — `docs/HANDOFF.md`, «Грабли»).

Пока нет аккаунтов (сервер, хранилище, мониторинг, Apple Developer, Google,
бот) — настоящие кнопки входа и выкладка ждут Дашу; локально, в тестах и на
стенде вход — подменой, которая в бою выключена и это проверено тестом.

Порядок — частями, каждая вливается в `main`, когда зелёная. Решение Даши
09.10.2026: экзамен как понятие в базе и договоре, админка и конвейер контента
идут сейчас, параллельно с раундом дизайна; CI — после них. Готовы: договор,
сервер Go, база и гейт под Go; приложения Apple (iPhone, iPad, Mac) и Android —
раньше веба, по просьбе Даши 06.10.2026; веб — мини-апп и сайт (вход, «Сегодня»,
разделы-заглушки, настройки; e2e на iPhone, Android и трёх ширинах сайта);
первый срез тренировок — на всех платформах (§5). Дальше (решение Даши
08.10.2026):

1. CI в GitHub Actions на все части (для Apple — раннер macOS, Postgres без
   Docker; e2e веба — с браузерами из того же образа Playwright, что
   `compose.yaml`; `tokens.yml` — на корневой lockfile и Node 24),
   `docs/TESTING.md`, агенты ревью `gp-review-access` и `gp-review-errors` под Go
   и Postgres и правила путей линз в `/gp-review` под `server/` и `apps/`, тест на
   `.claude/hooks/session-git.sh`; вместе с ним — хвосты каркаса из Issues;
2. админка (§4);
3. сервер, стенд, копии базы, мониторинг, бот (имя и тексты —
   `scripts/setup-bot.mjs`, вебхук на Go) — перед бетой (решение Даши
   08.10.2026), когда Даша заведёт аккаунты; до того админка и база контента —
   на Маке. Последним шагом — `DEPLOY_ENABLED=true` в GitHub.

## 3. Шкала баллов пробника

Решение Даши 05.10.2026: после пробного экзамена показываем верные и неверные
и примерный балл с пометкой «наша оценка, не официальная». Исследование, как
ETS считает баллы, и предложенный алгоритм нашей оценки (маршрут после первой
секции, таблица-якорь, диапазон, эссе, перцентили, сверка с баллами беты) —
`docs/SCORING.md`; решения Даши по нему приняты 06.10.2026 (три варианта
второй секции, диапазон крупно, скриншоты результата GRE с бета-пользователей,
оценка эссе ±1 с пометкой «бета»).

## 4. Контент

Порядок подготовки — `AGENTS.md`, «Контент заданий». Сначала GRE, следом TOEFL
того же масштаба (решение Даши 09.10.2026: около 150 заданий на каждую из
четырёх частей, 2 пробника, 600–1000 академических слов, теория по типам
заданий; озвучка Listening заранее; Speaking и Writing — живая оценка с
лимитом, `PRODUCT.md`, «TOEFL»). Объём GRE на старте:

- 1000 слов (полная карточка, озвучка без сети);
- 200 заданий Verbal, 200 по математике (частично шаблонами — число
  подставляет приложение и само считает ключ), у каждого разметка: тема, тип,
  сложность; 2 пробных экзамена с тремя вариантами второй секции (лёгкий,
  средний, сложный) — 228 вопросов на оба пробника;
- 40–60 тем теории;
- темы эссе в формате GRE (свои; на пул ETS — ссылка) и эталонные эссе с
  оценками для сверки модели.

Конвейер: генерация Claude Opus 5.5 пакетами → независимое решение для
проверки ключа → веб-админка, где Даша принимает, правит или возвращает →
публикация; каждую ночь — выгрузка в приватный репозиторий. Эталоны для
промптов генерации и проверки ключа; каждый случай трижды подряд.

Проверка Даши — около 65–75 часов: главное, от чего зависит дата запуска.
Админка и конвейер — сейчас, параллельно с дизайном, до CI (решение Даши
09.10.2026). Перед ними — отдельный допрос.

## 5. Фичи первой версии

Примерный порядок, каждая — с тестами по `AGENTS.md`:

1. тренировки: конструктор, режимы «Практика» и «Проверка», разбор ошибки
   RU/EN, калькулятор, «Сообщить об ошибке». Первый срез — задания с выбором
   ответа (Text Completion с 1–3 пропусками, Sentence Equivalence, Quantitative
   Comparison, обычный выбор) — готов на сервере, в Android, вебе и Apple
   (решения Даши 06.10.2026: «Проверка» в темпе экзамена, время вышло — итог
   сразу, «не успел» отдельно от ошибок; в «Практике» «Не знаю» вместо
   пропуска; 08.10.2026: на iPad и Mac — раскладка сайта, макеты `web-R*`,
   вопрос слева, разбор справа, клавиши). Планшет Android пока показывает
   колонку по центру — две колонки и там — открыто. Правила тренировки на всех
   платформах сверяются с общим файлом примеров (`docs/HANDOFF.md`, «Договор
   API»). Дальше: второй срез — Reading
   Comprehension; третий — ввод числа, несколько верных, Data Interpretation и
   калькулятор ETS; формулы Quant — до генерации контента (#23);

   «Повторить мои ошибки»; история, точность по разделам, типам и темам,
   примерный балл, календарь занятий (решение Даши 09.10.2026, `PRODUCT.md`,
   «Статистика и история»);
3. словарь: интервальное повторение с проверкой;
4. теория по темам;
5. пробный экзамен один в один как настоящий, отдельные секции;
6. эссе с оценкой Claude Sonnet 5.5 — после сверки на эталонах (не тянет —
   Opus 5.5), с лимитом на человека;
7. оплата: бесплатная бета 4–6 недель → одна подписка, три кассы (Tribute,
   Apple, Google Play — `PRODUCT.md`, «Stack»), скидка бета-пользователям,
   7 дней пробного новым; вход через Telegram, Apple, Google.

## 6. Приложения на Swift и Kotlin — в первой версии

Решение Даши 05.10.2026: вместе с вебом — Swift (SwiftUI) для iPhone, iPad и
Mac и Kotlin (Jetpack Compose) для Android. Правила тестов, проверка на
симуляторе и эмуляторе, сборка и публикация в магазины решаются вместе с
каркасом; публикация и платные аккаунты разработчика — только с согласия Даши.
Android — чистый Kotlin, без Skip (решение Даши 05.10.2026, `PRODUCT.md`,
«Platform»). Android дальше растёт фича за фичей сквозняком — договор API →
сервер и база → экраны → тесты (решение Даши 06.10.2026): все экраны «Шагов» —
настоящие, с логикой на сервере, а не на демо-данных. Бэкенд на своём сервере позволит приложениям работать из России
без VPN.
