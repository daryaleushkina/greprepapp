# Бриф: шесть направлений дизайна мини-аппа (подготовка к GRE®)

Ты рисуешь ОДНО направление (его буква — в задании) — шесть экранов телефона
на холсте Design. Всего направлений шесть (А–Е), их делают параллельно другие
агенты; описания всех — ниже, чтобы твоё не было похоже на соседние.
Владелица продукта — Даша; она будет сравнивать направления и править их
прямо на холсте. Цель — чтобы каждое направление было цельным,
узнаваемым без текста миром и при этом удобным инструментом для подготовки.

## 1. Продукт в двух абзацах

Мини-апп Telegram для русскоязычных, которые готовятся к экзамену GRE®
General Test, чтобы поступить за рубеж. Заменяет репетитора: тренировки по
разделам (Verbal, Quant — математика, эссе — Analytical Writing), словарь,
пробный экзамен один в один как настоящий и главное — разбор каждой ошибки на
русском и английском с советом, что повторить. Задания — на английском,
интерфейс — русский (на холсте — русский).

Часть аудитории — люди с СДВГ. Правила интерфейса (W3C COGA): одно главное
действие на экране; виден конец сессии («4 из 10»); таймер только там, где он
часть задачи (экзамен, режим «Проверка»); никаких всплывающих окон, серий,
очков, лиг, конфетти и мотивационных лозунгов; разбор раскрывается постепенно;
условие, твой ответ и верный ответ видны рядом; не держать ничего в памяти.
Простота, а не минимализм: нужное видно сразу.

## 2. Формат файла (.dc.html) — обязательно

Каждый экран — один самодостаточный файл. Скелет (копировать точно,
строку `<script src="./support.js"></script>` — дословно):

```html
<!doctype html>
<html lang="ru">
<head>
<meta charset="utf-8">
<title>Маршрут — Главная</title>
<script src="./support.js"></script>
</head>
<body>
<x-dc>
<helmet>
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Onest:wght@400;500;600;700&amp;display=swap">
<style>
body{margin:0}
a{color:#0A6CB4}a:hover{color:#08548C}
button{font:inherit;cursor:pointer}
</style>
</helmet>
<div style="width: 390px; height: 844px; overflow: hidden; position: relative; box-sizing: border-box; font-family: 'Onest', sans-serif; color: #121417; background: #FFFFFF; display: flex; flex-direction: column">
  ... экран ...
</div>
</x-dc>
<script type="text/x-dc" data-dc-script data-props='{"$preview":{"width":390,"height":844}}'>
class Component extends DCLogic {
renderVals() {
return {};
}
}
</script>
</body>
</html>
```

Правила, которые ломают молча:

- закрывать каждый не-пустой элемент, кавычки у каждого атрибута; `&` в
  атрибутах — `&amp;`;
- корень — ровно 390×844 px, `overflow: hidden`; что не влезло — обрезается
  снизу, как прокрученный экран (не сжимать шрифт ради «влезло»);
- стили — инлайн `style="…"` (их правит панель свойств); в `<helmet><style>`
  — только основы: `body{margin:0}`, цвета `a`/`a:hover`, `:active`,
  `:focus-visible`, `::selection`, `@media (prefers-reduced-motion)`;
  классы в helmet — только для состояний, которые инлайн не выразить;
- раскладка — flex или grid с `gap`; абсолютное позиционирование — только
  для линий, точек, наложений;
- `{{дырка}}` — только точечный путь к значению из `renderVals()`, никаких
  выражений (`{{a+b}}`, `{{!x}}` не работают);
- весь интерфейс — разметка внутри `<x-dc>`, не создавать DOM скриптом;
- текст писать буквально в разметке (Даша будет перепечатывать на месте), не
  через пропсы; `data-props` — только `$preview`;
- сеть — только `<link>` Google Fonts `css2` в helmet;
- иконки — инлайн SVG одной толщины линии (stroke), никогда эмодзи и никогда
  символы Юникода вместо иконок (✓ ✕ ★ → ← ⋯ — нельзя, рисовать SVG);
- никаких `<iframe>`, `<object>`, `<embed>`, глобальных обработчиков клавиш;
- настоящие `<button>`, `<a href>`, `<input>` + `<label>`, даже в статичном
  макете; у кнопок-иконок `aria-label`; никаких `onClick` на div/span;
- цели касания ≥ 44 px; текст ≥ 13 px (подписи вкладок — 11 px допустимо);
  контраст текста ≥ 4.5:1 (крупный ≥ 3:1), серые подписи — темнее, чем
  хочется; цвета, которые надо различать, отличаются и светлотой.

**Интерактивный экран — только «Вопрос и разбор» (X3):** переключатель RU/EN
должен работать. Образец логики:

```html
<button type="button" aria-pressed="{{ruPressed}}" onClick="{{setRu}}" style="…{{ruStyle}}">RU</button>
<button type="button" aria-pressed="{{enPressed}}" onClick="{{setEn}}" style="…{{enStyle}}">EN</button>
<sc-if value="{{isRu}}" hint-placeholder-val="{{ true }}"> …русский разбор… </sc-if>
<sc-if value="{{isEn}}" hint-placeholder-val="{{ false }}"> …английский разбор… </sc-if>
```

```js
class Component extends DCLogic {
renderVals() {
const lang = (this.state && this.state.lang) || 'ru';
const on = 'background: #121417; color: #FFFFFF;';
const off = 'background: transparent; color: #121417;';
return {
isRu: lang === 'ru', isEn: lang === 'en',
ruPressed: lang === 'ru' ? 'true' : 'false', enPressed: lang === 'en' ? 'true' : 'false',
ruStyle: lang === 'ru' ? on : off, enStyle: lang === 'en' ? on : off,
setRu: () => this.setState({ lang: 'ru' }), setEn: () => this.setState({ lang: 'en' })
};
}
}
```

(Дырка в style допустима только для таких живых состояний; остальные цвета —
литералами в инлайне.)

## 4. Содержимое экранов — одно на все направления

Тексты ниже — точные; можно сокращать подписи, если направление того требует,
но смысл и цифры не менять. Всё содержимое — пример (не настоящий контент).
Запреты: никаких надзаголовков-«кикеров» (мелкая строка капсом над
заголовком) — заголовок говорит сам; никаких одинаковых карточек
«иконка + заголовок + текст» сеткой; никаких «героических цифр»
(огромное число + подпись + акцент); никаких колец прогресса и спарклайнов.

2. **Главное действие** — продолжить начатое: «Продолжить тренировку» ·

### X2 — Конструктор тренировки (`?2-Builder.dc.html`)

Шапка: «Назад» · имя · меню. MainButton: «Начать · 10 вопросов».

Решение Даши: всё уже выбрано (как в прошлый раз), «Начать» видно сразу,
настройки раскрываются по желанию. Конструктор обязан быть удобным при
большом выборе.

1. Заголовок «Новая тренировка».
2. Сводка одной фразой, каждая часть — нажимаемая (раскрывает свой выбор):
   «Verbal · Text Completion · все темы · любая сложность · 10 вопросов ·
   Практика».
3. Раздел (переключатель): Verbal (выбран) / Quant / Эссе.
4. Раскрыт один параметр — «Тип задания»: Reading Comprehension · Text
   Completion (выбран) · Sentence Equivalence; у каждого — «доступно 64»,
   «доступно 58», «доступно 41».
5. Количество: 5 / 10 (выбрано) / 20.
6. Режим: «Практика — разбор после каждого вопроса, без таймера» (выбран) /
   «Проверка — разбор в конце, с таймером ~15 мин».
7. Быстрые наборы (вторично): «Как в прошлый раз», «Мои ошибки · 23».
8. Итог над кнопкой: «~15 мин · разбор после каждого вопроса».

### X3 — Вопрос и разбор (`?3-Question.dc.html`) — интерактивный

Шапка: «Назад» · имя · меню. MainButton: «Следующий вопрос».
Состояние: человек ответил неверно, разбор раскрыт на второй уровень.

1. Прогресс: «4 из 10» — и видно, где конец сессии; вопрос 2 был неверным.
2. Тип: «Text Completion».
3. Текст задания (на английском, читаемым текстовым шрифтом):
   «Although the committee's report was praised for its thoroughness, critics
   noted that its conclusions were oddly ______, hedging on nearly every
   recommendation it made.»
4. Варианты: (A) equivocal (B) incisive (C) exhaustive (D) dogmatic
   (E) lucid. Человек выбрал **C — exhaustive** (неверно); верно —
   **A — equivocal**. Оба отмечены явно (не только цветом: значок + слово).
5. Вердикт одной фразой: «Неверно. Верный ответ — A, equivocal».
6. Переключатель RU / EN (работает).
7. Разбор RU:
   - «Подсказка — „hedging on nearly every recommendation“: выводы
     уклончивы. Это и есть equivocal — двусмысленный, уклончивый.»
   - «Ваш ответ — exhaustive („исчерпывающий“). Соблазняет, потому что рядом
     стоит thoroughness. Но although требует контраста с похвалой, а не её
     повтора.»
   Разбор EN:
   - «The clue is "hedging on nearly every recommendation": the conclusions
     avoided commitment. That is what equivocal means — deliberately
     ambiguous.»
   - «Your answer, exhaustive ("covering everything"), is tempting because
     thoroughness appears nearby. But although signals a contrast with the
     praise, not a repeat of it.»
8. «Тема: слова-сигналы контраста · теория 3 мин» (ссылка) и мелко
   «Сообщить об ошибке» (ссылка).

### X4 — Слово (`?4-Word.dc.html`)

Шапка: «Назад» · имя · меню. MainButton: «Следующее слово».
Состояние: сессия повторения слов, человек только что верно выбрал перевод;
показана полная карточка.

1. Прогресс «Слова · 3 из 12».
2. Итог: «Верно. Следующее повторение — через 4 дня».
3. Слово **equivocal**, транскрипция [ɪˈkwɪvək(ə)l], adj., кнопка
   «Послушать» (иконка динамика + aria-label).
4. Значения:
   - 1. ambiguous or evasive, open to more than one interpretation —
     двусмысленный, уклончивый. *The minister's equivocal answer satisfied no
     one.* — Двусмысленный ответ министра никого не устроил.
   - 2. uncertain, inconclusive — неопределённый, неоднозначный (о
     результатах). *The results of the trial were equivocal.* — Результаты
     испытания оказались неоднозначными.
5. Синонимы: ambiguous, evasive, noncommittal. Антонимы: unequivocal,
   clear-cut, categorical.
6. Мелко: «Выучено — когда ответите верно 4 раза подряд с перерывами» и
   этап памяти (например, 2 из 4).

## 5. Шесть направлений

Общее: светлая тема на этом этапе. Цвета — свои у всех, кроме Г (тема
Telegram). Имя в шапке — имя направления. У каждого направления — один
«фирменный ход», который виден на каждом экране, но не мешает задаче.

### А · Схема — имя «Маршрут» (шрифт Onest 400/500/600/700)

Мир: схема метро и навигационные указатели. Разделы — линии своего цвета:
Verbal `#0A6CB4`, Quant `#0E7C3E`, Эссе `#7B3A97`, Слова `#E26A12`; значок
линии — кружок цвета линии с буквой: V, Q, AW, Сл (белый текст; для оранжевого
— тёмный `#121417`). Фон `#FFFFFF`, поверхность `#F3F4F6`, текст `#121417`,
вторичный `#4A4F57`, линейки `#E2E4E8`. Ошибка `#C81E2A` (+ значок),
верно — чёрная галочка-SVG (не зелёный: зелёный занят Quant). Главное
действие — `#121417`, белый текст, скругление 10. Линии — 6 px, станции —
кружки 14 px с белой серединой и обводкой цвета линии, текущая станция —
крупнее (22 px), пройденная — залитая; пересадка — два кружка, соединённые
перемычкой. Подписи станций — 13 px, 500. Заголовки 28 px, 700,
трекинг −0.02em, цифры табличные (`font-variant-numeric: tabular-nums`).
Фирменный ход: сессия — линия с 10 станциями (X3, X4: ты на станции 4);
главная — маленькая схема четырёх линий с маршрутом «сегодня»; конструктор —
«проложить маршрут» (линия = раздел, станции = темы, число остановок =
вопросы); экзамен — линия секций AW → V1 → V2 → Q1 → Q2; слабые места —
станции на линиях, где размер/отметка показывает долю ошибок; слово — линия
памяти из 4 станций до «выучено». Схемы — из отдельных div (линии и кружки),
а не одной картинкой. В вопросе схемы мало: только линия прогресса сверху.

### Б · Поля — имя «Поля» (PT Sans 400/700, PT Serif 400/700 для текста заданий, Caveat 500/700 для пометок)

Мир: школьная тетрадь в клетку и красная ручка репетитора. Страница
`#FFFFFF` с еле заметной голубой клеткой 20 px (`#DDEAF6`, фон корня:
`background-image: linear-gradient(#DDEAF6 1px, transparent 1px),
linear-gradient(90deg, #DDEAF6 1px, transparent 1px); background-size:
20px 20px`), красная линия полей `#E58A8E` 1.5 px слева на x = 44 px —
поля шириной 44 px для пометок; содержимое — от 56 px. Текст `#1A1A1A`,
вторичный `#555B66`, синие чернила `#1D3A9C` (ответы человека, главное
действие), красная ручка `#C8222B` (разбор, исправления, пометки на полях).
Главное действие — `#1D3A9C`, белый текст, скругление 10. Содержимое
выравнивается по клетке (отступы кратны 20 px, где можно).
Фирменный ход: в X3 неверный вариант зачёркнут рукописным красным штрихом
(SVG-путь), верный обведён красным от руки (SVG), на полях — красная пометка
Caveat («4/10», «!»); разбор — блок красной ручкой под вариантами (основной
текст разбора — PT Sans красным `#C8222B` или тёмным с красной пометкой; не
длинные абзацы Caveat — им только короткие пометки). Главная — заголовок как
в тетради: «Пятое октября» и под ним «Тренировка» (Caveat, синие чернила).
X6 называется «Работа над ошибками» — привычный со школы ритуал. Экзамен —
строже: клетка остаётся, рукописного нет (экзамен как экзамен).

### В · Бланк — имя «Ключ» (Golos Text 400/500/600/700, PT Mono 400/700 для номеров, счётчиков и времени)

Мир: машиночитаемый бланк ответов экзамена. Фон `#FFFFFF`; «краска бланка»

## 6. Как сдавать работу

- Писать каждый файл **инструментом записи файлов** (Write), по одному на
  экран, сразу целиком; никаких скриптов, генерирующих файлы, никаких
  шаблонизаторов.
- Путь: `<ROOT>/project/<имя файла>`, где ROOT указан в задании. Имена
  файлов: `<Буква>1-Home.dc.html`, `<Буква>2-Builder.dc.html`,
  `<Буква>3-Question.dc.html`, `<Буква>4-Word.dc.html`,
  `<Буква>5-Exam.dc.html`, `<Буква>6-Weak.dc.html` (буква — латинская:
  A, B, C, D, E, F); для D ещё `D7-HomeDark.dc.html`.
- `<title>` каждого файла — «Имя — экран», например «Маршрут — Главная».
- **Не открывать и не рендерить** файлы в браузере, не делать скриншотов, не
  ставить пакетов, не публиковать, не трогать git и никакие файлы вне своих.
  Один раз перечитать свои файлы глазами на закрытые теги и правила из
  раздела 2 — и всё.
- В ответе — только список записанных файлов и одна-две строки о том, что
  получилось и где сомневаешься.
