# /gp-review — панель ревью перед пушем фичи

Запускать перед пушем фичи **вместе со встроенным `/code-review`**: тот ищет общие ошибки, эта панель — нарушения правил GrePrepApp (каждый запрос ограничен `user_id`, платный контент без проверки прав, тихие сбои, правила тестов из AGENTS.md, платформа Telegram). Правка задевает интерфейс — ещё `interface-review`. ⚠️ Агенты линз ещё написаны под LifeCommit (Worker, Supabase, `src/`, задача #9): их находки сверяй с кодом особенно строго. Не встраивать в `scripts/hooks/pre-push`: ревью агентами медленное и недетерминированное, а хук должен давать один и тот же ответ на один и тот же код.

Вызов этой команды — согласие Даши на запуск Workflow.

## 1. Запуск

База: `$ARGUMENTS`, если пусто — `origin/main`.

Запусти Workflow `gp-review` с `args: { "base": "<база>" }` (объект, не строка). Если по имени не находится — `Workflow({ scriptPath: ".claude/workflows/gp-review.js", args: { "base": "<база>" } })`.

Что внутри (`.claude/workflows/gp-review.js`): сбор изменений относительно `merge-base(база, HEAD)` вместе с правками без коммита и новыми файлами → линзы параллельно (`gp-review-errors` и `gp-review-tests` всегда; `gp-review-access` при `server/`, `api/`, `packages/api-client/`, `apps/*/src/{auth,session}/`; `gp-review-ui` при `apps/web/src/`) → склейка дублей → `gp-skeptic` пытается опровергнуть каждый HIGH/CRITICAL. Линза доступа снимает блокер только при уверенном опровержении, остальные — понижают неуверенно подтверждённое до рекомендации.

## 2. Итог — по-русски, коротко

- `NOTHING_TO_REVIEW` — так и сказать, на этом всё.
- Вердикт одной строкой: «можно пушить» (`APPROVE`) или «есть блокеры» (`CHANGES_REQUESTED`). Если `incomplete` — назвать линзы из `failedLenses` и сказать, что одобрения нет, потому что они не отработали; предложить перезапуск.
- Каждый блокер: `[ВАЖНОСТЬ] заголовок — файл:строка`, одной-двумя фразами суть (`proof`), исправление (`fix`), пометка скептика (`note`).
- Рекомендации — коротким списком, по одной строке, без подробностей.
- «Не проверено» — сводка `residualRisk` по линзам, если там что-то существенное (например, «RED не проверен механически»).

Ключевые блокеры перед показом проверь сама по коду: агенты могут ошибаться и после скептика.

## 3. Решение по каждому блокеру — кнопками

AskUserQuestion пачками по 4 вопроса (по вопросу на блокер), варианты:

- **Чинить** (Recommended, если блокер подтверждён скептиком) — исправить: заданием Codex, мелочь — самой. Баг — сначала тест, который его ловит и падает, потом исправление (AGENTS.md).
- **Оставить с пометкой** — не чинить; рядом с кодом комментарий «(решение Даши <дата>)», почему так задумано, чтобы следующее ревью не поднимало это снова.
- **Отложить** — не чинить сейчас; задача в GitHub Issues с файлом:строкой и сутью, затем обновить зеркало `docs/BACKLOG.md` (AGENTS.md, «Куда что записывается»).

## 4. После исправлений

- Повторить `/gp-review` один раз — только чтобы убедиться, что блокеры закрыты и не появились новые. Больше двух кругов ревью не делать: оставшееся — снова кнопками.
- Дальше обычный путь: коммит и вливание в `main`; хук `pre-push` (или GitHub Actions для пуша из облака) прогонит typecheck, lint, покрытие, e2e, сборку и деплой.
