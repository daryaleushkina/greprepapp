Проведи аудит путей нажатий в GrePrepApp (основа — click-path-audit из github.com/affaan-m/ecc). Аргументы: `$ARGUMENTS`.

Дорого: запускать перед релизом, после большого рефакторинга, после правки общего состояния или когда кнопка «ничего не делает». Нужен работающий стенд, то есть каркас: без `package.json` и `src/` проверять нечего — так и скажи.

## 1. Объём

- `all` (по умолчанию) — все части ниже.
- Экран или файл — только та часть, куда он входит.
- `state` — после правки общего состояния (модульные кэши и загрузчики, общие хуки данных, счётчик правок, отложенные действия, `src/telegram/hooks.ts`, состояние `src/App.tsx`): найди всех, кто пользуется изменёнными функциями (`grep`), и проверь только эти экраны.

Части собери сама по `src/screens` и `src/components`: 3–5 частей, обычно по разделам нижней панели (экраны раздела, их шторки и компоненты); каркас приложения (`src/App.tsx`: маршруты, нижняя панель, перечитывание, первый запуск) — отдельная часть. Каждой части — короткий префикс латиницей (имя раздела).

## 2. Карта общего состояния — сначала, сама

Построй её до запуска агентов (это общий вход для всех) и запиши в `e2e/_explore/click-path/map.md` (папка в `.gitignore`):

```
МОДУЛЬ: src/<модуль>.ts
  load.<что>(…)  → пишет <кэш>; сверяет / НЕ сверяет счётчик правок
  once(key)      → повторный вызов с тем же ключом получает тот же промис (дедупликация)
  warm(p)        → глотает ошибку
  ...
ОПАСНЫЕ МЕСТА: кто сбрасывает или затирает чужое состояние; кто глотает ошибки; какие ответы не сверяются с последней правкой
```

Пройди: модульные кэши и загрузчики, общие хуки данных, счётчик правок (если есть), отложенные действия (удаление с «Вернуть», отправка по таймеру), `src/telegram/hooks.ts`, состояние `src/App.tsx` (маршрут, общий кэш, перечитывание, флаги шторок), ключи `localStorage`. Для каждого действия: что ставит, что сбрасывает попутно, сверяет ли устаревшие ответы, что делает с ошибкой.

## 3. Стенд

⚠️ **Шаги стенда ниже и сами агенты — ещё из LifeCommit** (порт 5173, Supabase, `src/`) и в GrePrep не работают. Здесь Postgres и браузеры поднимает `docker compose --profile e2e up -d --wait postgres browsers`, а API (8093), подменный OIDC (8094) и сайт (5191) — сам `pnpm e2e` на каждый прогон, и уже запущенный стенд он не переиспользует (`reuseExistingServer: false` в `playwright.config.ts`): параллельные агенты столкнутся портами. До переписывания (задача #9) не запускать — сказать об этом Даше и проверить руками.

Находки подтверждаются сценариями, поэтому стенд нужен:
1. `pnpm exec supabase status >/dev/null 2>&1 || pnpm db:start`.
2. `curl -sf http://localhost:5173 >/dev/null` — не отвечает: `pnpm dev --port 5173 --strictPort` в фоне, дождаться ответа. Агенты сервер не поднимают (порт один).

## 4. Агенты по частям — параллельно

Одним сообщением запусти агентов `gp-click-path` (`.claude/agents/gp-click-path.md`) — по одному на часть. Каждому: экраны и файлы части, путь к карте, префикс. Напомни: стенд поднят, писать только в `e2e/_explore/click-path/`, код не править.

## 5. Сведение

1. Склей одинаковые находки (одна причина в общем модуле — одна находка, со списком затронутых кнопок).
2. Каждую находку перепроверь сама: `E2E_EXPLORE=1 pnpm e2e <спек> --project=<проект> --retries=0 --output=e2e/_explore/out/check`. Не падает на симптоме — выкинь.
3. Покажи сводку: сколько точек пройдено, таблица подтверждённых находок (ID, важность, кнопка, шаблон, коротко), отдельно «не подтверждено» и что агенты дописали к карте.

## 6. Решение — кнопками

По каждой подтверждённой находке — AskUserQuestion, **по 4 вопроса за вызов**: «Чинить» / «Отложить» (задача в GitHub Issues) / «Не баг» (решение Даши — запишу, чтобы не поднимать снова).

- **Чинить** — заданием Codex (мелочь — сама), по AGENTS.md: сценарий переезжает из `e2e/_explore/click-path/` в настоящий `e2e/<раздел>.spec.ts` (или в dom-тест `src/**/*.test.tsx`, если так проще и точнее), убедиться, что падает, исправить, позеленеть. Причина в общем модуле — чинить там, а не в каждом экране. В конце — `pnpm typecheck && pnpm lint && pnpm coverage && pnpm e2e`.
- **Отложить** — задача в GitHub Issues: симптом, где, как воспроизвести (спек); затем обновить зеркало `docs/BACKLOG.md` (как — в AGENTS.md, «Куда что записывается»).
- **Не баг** — комментарий рядом с кодом «(решение Даши <дата>)»; если решение о поведении в целом, а не об одном месте, — ещё и в `docs/HANDOFF.md`, правкой на месте.
